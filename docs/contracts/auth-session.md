# Authentication and session contract

Public registration always creates a `client` and never accepts an authorization role. Passwords use Argon2id. Access JWTs expire after 15 minutes and remain in memory in the operations client. Opaque refresh tokens expire after 30 days, are stored only as hashes server-side, and are delivered through an HttpOnly cookie that is Secure in production, scoped to `/api/v1/auth`, with `SameSite=Lax` by default (D-026). D-088 (pending owner confirmation) makes the attribute configuration (`REFRESH_COOKIE_SAMESITE`): a two-site deployment sets `none` (always with `Secure`), and the cookie-bearing auth routes (`/api/v1/auth/refresh`, `/logout`) refuse any request whose `Origin` is not in `CORS_ALLOWED_ORIGINS` (`401 ORIGIN_NOT_ALLOWED`, cookie cleared, token not consumed); requests without an Origin are unchanged. Regression: `test_auth.py::test_cookie_samesite_is_configurable_and_cross_site_origin_is_guarded` (both values).

Refresh tokens rotate on every refresh. Reuse of a rotated token revokes all active sessions for that user. Protected requests validate the access-token signature and claims, session state, expiry, user deletion state, and matching user/session security versions.
