# 01_TECH_STACK.md — Locked Technology and Engineering Choices

## General

Architecture:
- monorepo;
- FastAPI backend;
- PostgreSQL authoritative database;
- React/Vite operations PWA;
- Next.js App Router public storefront;
- TypeScript;
- English/Arabic from foundation.

Do not replace a locked technology without user approval.

## Backend

Required:
- Python
- FastAPI
- PostgreSQL
- SQLAlchemy 2.x
- Alembic
- Pydantic v2
- Pydantic Settings
- PostgreSQL driver: psycopg 3
- password hashing: Argon2id via `pwdlib[argon2]`
- JWT: PyJWT
- email validation: Pydantic EmailStr / email-validator
- phone parsing/normalization: `phonenumbers`
- OpenAPI/Swagger generated by FastAPI

Database access:
- SQLAlchemy 2.x synchronous transaction model initially;
- service/repository layer;
- explicit transactions for multi-record invariants;
- PostgreSQL RLS for tenant tables.

Do not switch the backend to async SQLAlchemy merely for preference. That would be an architecture change requiring approval.

## Operations web app

Required:
- React
- TypeScript strict mode
- Vite
- React Router
- TanStack Query for server-state fetching/mutations
- React Hook Form + Zod for client-side form ergonomics
- i18next + react-i18next for EN/AR
- IndexedDB
- Dexie beginning in the offline phase
- service worker/PWA support
- typed API layer

Access-token handling:
- access token stays in memory;
- protected API uses `Authorization: Bearer`;
- refresh token is HttpOnly/Secure cookie according to auth contract;
- never store refresh token in localStorage/IndexedDB.

Design:
- no generic UI/admin framework is required;
- use semantic components and design tokens/CSS variables;
- final visual direction comes from `05_DESIGN_REFERENCES.md` and user-approved design work;
- do not lock the project to a design framework without approval.

## Storefront

Required beginning Phase 5:
- Next.js App Router
- TypeScript
- bilingual EN/AR
- tenant-slug routing
- mobile-first public pages
- guest checkout
- shared API contracts/types where appropriate

Do not create a customer-login system.

## Type/API contracts

Production API namespace:
- `/api/v1/...`

Mandatory training endpoints remain at exact root paths:
- `/register`
- `/login`
- `/users...`
- `/stats...`

Use RFC3339 timestamps.
Use ISO currency codes.

A generated TypeScript API contract/client may be used from FastAPI OpenAPI. Do not duplicate backend business rules in frontend packages.

## Money

PostgreSQL:
- `NUMERIC(20,4)`

Application:
- Decimal arithmetic
- `ROUND_HALF_UP`
- no binary floating point for authoritative money.

## Local/offline

- IndexedDB is operational local projection;
- Dexie is the IndexedDB abstraction;
- outbox/idempotency/version protocol is defined in Phase 4;
- local UUIDs for offline-created entities;
- official invoice/revision sequence values are server-assigned.

## Media

Provider-neutral object-storage abstraction.

Before a real production storage provider is selected:
- keep interface/provider separation;
- use a safe local/dev adapter if needed.

Do not choose a paid/cloud provider without user approval.

Accepted product images:
- JPEG
- PNG
- WebP
- no user SVG upload

Server validates/re-encodes images.

## Google backup

- Google OAuth
- Google Drive API
- encrypted backup/export
- exact OAuth scopes are a Phase 4 gate and require explicit user approval.

## Routing

Online routing/geocoding provider is intentionally undecided until Phase 7 because Lebanon coverage/pricing can change.

The implementation agent must ask the user before selecting the provider.

## Testing

Backend:
- pytest
- FastAPI test client/httpx as appropriate
- integration tests against real PostgreSQL behavior

Frontend:
- Vitest
- React Testing Library

End-to-end:
- Playwright

Required test categories:
- unit
- integration
- API/contract
- RLS/authorization
- financial invariants/property-style
- sync idempotency/conflict
- E2E critical flows

Do not use SQLite as the only database for tests that depend on PostgreSQL semantics.

## Quality

Python:
- Ruff
- static typing with mypy if compatible with project setup

TypeScript:
- `tsc --noEmit`
- ESLint

Use strict TypeScript.

## Local development

Prefer:
- Docker Compose for PostgreSQL/test infrastructure if Docker is available;
- `.env.example` with names only, never secrets;
- migrations build database from zero.

If the user's environment cannot run Docker, ask before changing the development-database strategy.

## Dependencies and versions

Do not hardcode arbitrary patch versions in these instruction files.

At bootstrap:
- use stable non-prerelease versions compatible with the locked major technologies;
- lock exact resolved versions in repository lockfiles;
- preserve existing compatible project versions if the repo is not empty;
- do not perform major dependency upgrades later without user approval.

Adding a new dependency category not listed here requires approval unless it is a tiny transitive/mechanical test utility with no architectural impact.
